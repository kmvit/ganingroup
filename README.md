# Корпоративный сайт на Django

Вёрстка варианта «Монолит», перенесённая на Django-шаблоны.

## Запуск

```bash
.venv/bin/python manage.py runserver
```

Сайт: http://127.0.0.1:8000/ · Админка: http://127.0.0.1:8000/admin/

Создать доступ в админку (пароль задаёте сами):

```bash
.venv/bin/python manage.py createsuperuser
```

## Приложения

Проект разделён по смыслу — так же сгруппированы разделы в админке:

| Приложение | Что внутри |
|---|---|
| `core` | общие данные сайта, меню, страницы и плитки |
| `content` | цифры, направления, объекты, люди, вакансии, документы |
| `calc` | марки бетона с ценами и зоны доставки |
| `leads` | заявки: ТКП, перевозчики, отклики на вакансии |
| `pages` | тонкий слой представления: маршруты, views, шаблоны, навигация, формы |

Модели переехали между приложениями без изменения таблиц: физические имена
(`pages_*`) закреплены через `db_table`, миграции переносят только состояние
Django. Поэтому данные на работающем сервере не затрагиваются.

## Структура

```
templates/
  base.html            общий каркас: head, шапка, подвал, модалки, мобменю
  base_bare.html       каркас без шапки/подвала (лист айдентики)
  partials/            header, footer, floats, modals, mmenu, theme_toggle, theme_js
  pages/               28 страниц + 404, каждая = extends base + block content
static/assets/         site.css и логотипы
pages/
  nav.py               ЕДИНЫЙ источник навигации + контекст-процессор
  views.py             таблица PAGES (путь → шаблон → active) + приём заявок
  urls.py              маршруты генерируются из PAGES
  forms.py             LeadForm, HaulerLeadForm (валидация телефона, согласие ПДн)
  models.py            Lead, HaulerLead
```

## Навигация

Пункты меню правятся в админке («Меню сайта»): дерево из разделов и подпунктов.
Шапка, подвал и мобильное меню собираются из одного дерева — пункт добавляется
в одном месте и появляется везде (в статике так терялся «Фасованный цемент»).
Колонка подвала может называться иначе, чем раздел меню («Продукция» →
«Направления») — это поле «Заголовок колонки в подвале».

Если меню в базе пустое, используется структура из `pages/nav.py` — сайт
не останется без навигации.

Новые страницы продукции создаются в админке: «Страницы (тексты и SEO)» →
«Добавить». Укажите название и адрес латиницей, заполните текст, загрузите
короткое MP4/WEBM и фото-постер для фонового видео шапки. Ссылка Google Drive
хранится как необязательная ссылка на исходный ролик. Чтобы вывести страницу в
меню, откройте «Меню сайта» → «Продукция», добавьте подпункт и выберите её в
поле «Страница продукции». Для плитки на странице «Продукция» добавьте запись
в «Направления (продукция)» и выберите ту же страницу в поле «Страница продукции».

## Формы

- «Запросить ТКП» — модалка на всех страницах → `POST /zayavka/tkp/`
- «Заявка перевозчика» — блок на «Карьере» → `POST /zayavka/perevozchik/`
- «Отклик на вакансию» с резюме → `POST /zayavka/vakansiya/`
  (PDF/DOC/DOCX/RTF/ODT до 10 МБ, файлы в `media/resume/ГГГГ-ММ/`)

## ИИ-ассистент для двух сайтов

Виджет на этом сайте и на `sd2-kmv.ru` обращается к `/assistant/chat/`.
Сервер ищет фрагменты среди опубликованных страниц двух сайтов и передаёт их
в модель через существующий шлюз `aivpnsaas`. Ключ остаётся только в окружении
сервера. Без настроенного шлюза чат сообщает о временной недоступности.
Заявки из чата сохраняются как обычные ТКП с пометкой сайта и страницы.

Перед первым вопросом посетитель отдельно соглашается на запись диалога.
Вопросы и ответы сохраняются в БД до достижения цели обработки либо отзыва
согласия; автоматического удаления диалогов через 30 дней нет. Адрес IP в БД не записывается,
используется HMAC-идентификатор. Суточный лимит по умолчанию отключён.
При `ASSISTANT_DAILY_LIMIT_ENABLED=1` действует лимит в 10 вопросов на IP
за календарные сутки по времени Москвы, суммарно по двум сайтам. Телефон и
почту в вопросе чат не принимает — для контактов служит отдельная форма.

Настройки сервера:

```text
ASSISTANT_API_URL=https://адрес-вашего-aivpnsaas
ASSISTANT_API_KEY=ключ-клиента-шлюза
ASSISTANT_MODEL=идентификатор-модели-из-каталога-шлюза
ASSISTANT_TRUST_X_REAL_IP=1
ASSISTANT_ENABLED=1
```

Для локальной работы эти значения можно записать в `ganin-site/.env`.
Файл автоматически читается Django и исключён из Git; заданные в системе
переменные имеют приоритет. В `ASSISTANT_API_KEY` укажите ключ клиента
`aivpnsaas` (`avs_...`), а не ключ OpenRouter. На СД2 ключ не нужен.

`ASSISTANT_TRUST_X_REAL_IP` включается только когда приложение доступно через свой
Nginx, который перезаписывает `X-Real-IP`; после развёртывания проверьте,
что разные посетители не получают один общий лимит из-за внешнего прокси.
Уберите `ASSISTANT_TRUST_X_REAL_IP` при прямом доступе к Django.
`ASSISTANT_ENABLED` по умолчанию выключен: виджет не показывается и API
не принимает запросы. На рабочих сайтах его пока не включать.
Для локальной проверки запустите этот проект с `ASSISTANT_ENABLED=1`
на `localhost:8000`. Во втором проекте задайте `ASSISTANT_ENABLED=1`
и `ASSISTANT_BASE_URL=http://localhost:8000`, затем запустите его на
`localhost:8899`. Сам виджет загружается сразу; согласие требуется перед
первым вопросом. Аналитика включается независимо от ассистента, только после
нажатия «Разрешить» в cookie-плашке.

После миграций наполните базу знаний и настройте ежедневные задания:

```bash
python manage.py refresh_assistant_knowledge
python manage.py purge_assistant_data
```

`refresh_assistant_knowledge` обновляет только успешно прочитанные страницы,
поэтому при сетевой ошибке старые данные сохраняются. На macOS локальному
Python может понадобиться `SSL_CERT_FILE=/etc/ssl/cert.pem`. Проверяйте число
обновлённых страниц: ноль означает, что индекс не обновился. В индекс входят
HTML-страницы; содержимое прикреплённых PDF пока не индексируется.
`purge_assistant_data` удаляет только счётчики за завершившиеся дни.
Диалоги удаляются отдельно при отзыве согласия или достижении цели обработки;
для этого нужен ответственный порядок рассмотрения таких случаев.

До публикации ассистента необходимо завершить проверку обработки ПДн и
внешнего маршрута модели, описанную в `docs/privacy-assistant-review.md`.
Виджет ассистента загружается на обеих площадках независимо от выбора
аналитики. Google Analytics и Яндекс.Метрика начинают работу только после
нажатия «Разрешить» на cookie-плашке.

Успех: редирект назад на `#tkp-ok` (модалка успеха на CSS `:target`).
Ошибка: редирект назад на якорь формы с текстом ошибки через `messages`.
Заявки видны в админке, можно отмечать «Обработана».

## Уведомления о заявках

Настраиваются в админке → «Общие данные сайта» → «Уведомления о заявках»:
адреса почты через запятую, токен телеграм-бота и ID чата. Пустые поля —
уведомления просто не отправляются, заявка всё равно сохраняется.

**Сбой отправки никогда не ломает заявку** — ошибка уходит в лог, клиент
видит подтверждение.

Почта на сервере (пароль в коде не хранится):

```bash
export EMAIL_HOST=smtp.yandex.ru EMAIL_HOST_USER=site@example.ru EMAIL_HOST_PASSWORD=... 
```

Без `EMAIL_HOST` письма печатаются в консоль — удобно для разработки.

## Темы

Тёмная по умолчанию, светлая — кнопка ☀/🌙 в шапке, выбор в `localStorage`
(`gg-theme`). Реализация в `static/assets/site.css` (слой `[data-theme="light"]`).

## Что редактируется через админку

**Общие данные сайта** (одна запись) — логотипы, телефоны, e-mail, адреса, режим
работы, слоган, год основания, реквизиты, текст подвала, ссылки UPEX и мессенджера.
Телефон подставляется на всех страницах; логотипы — с откатом на файлы вёрстки,
поэтому сайт не может остаться без логотипа.

**Контент по сущностям** — цифры холдинга, направления, объекты, отделы (контакты),
команда, отзывы, вакансии, документы, история группы, точки на карте присутствия.
У всех есть «Порядок» и «Показывать на сайте», у многих — загрузка фото.

**Страницы (тексты и SEO)** — у каждой из 28 страниц: H1, подзаголовок, основной
текст, SEO-title и description. Плитки на страницах правятся внутри страницы.
Добавлять/удалять страницы нельзя — набор задан вёрсткой.

**Заявки** — ТКП и перевозчиков, с отметкой «Обработана». Вручную не добавляются.

Заголовки хранятся вместе с разметкой (`<br>`, `<em>`) и выводятся через `|safe`,
поэтому дизайн крупных заголовков сохраняется.

Первичное заполнение базы контентом вёрстки:

```bash
.venv/bin/python manage.py seed_content
```

`--reset` очистит контентные таблицы перед заливкой (заявки не тронет).

## Фото и видео — всё грузится в админке

- **Первый экран главной** — видео (MP4/WEBM) и фото-замена: «Общие данные сайта».
- **Направления, объекты, команда, отзывы, отделы** — поле «Фото» у каждой записи.
- **Каталоги продукции** (бетон, ЖБИ, асфальт, инертные) — раздел «Каталог продукции»:
  название, бейджи, фото каждой позиции.
- **Шапки решений и кейса, фото сервисов, главное фото карточки товара** — поле
  «Фото страницы» в «Страницы (тексты и SEO)».
- **Галереи** (фото кейса, галерея товара) — блок «Фото в галерее страницы» там же.
- **Активы на «О группе»** — плитки страницы o_gruppe, блок assets (поле «Фото»).
- Пока файл не загружен — везде показывается серая заглушка вёрстки.
